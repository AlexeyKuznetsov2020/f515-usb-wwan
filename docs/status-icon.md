# Иконка сотовой сети: сигнал модема в статус-баре

В машине за мобильную сеть отвечает отдельный блок TBOX. **На этой машине его нет**
(`seres.platform.config.tbox=0`), поэтому штатная панель сотовую иконку не создаёт вовсе:
SystemUI заводит её только при `ID_CELLULAR_ENABLE=1`, иначе не подписывается на
`ID_CELLULAR_*` и в статус-баре не крестик, а пустое место.

Значит рисовать иконку штатной цепочкой некому, и весь этот путь из форка убран — вместе с
эмуляцией TBOX по SOME/IP, которая его обслуживала. Осталось то, что работает: **файл с
уровнем сигнала**, который читает Frida-твик `iSpaceToolbox` «Статус сети» и рисует иконку
сам.

## Как это устроено

```
tbox-icon.sh start
        |
        v
   tboxwire.jar (app_process)
        |  опрашивает модем раз в 15 с
        |    ppp    — AT+CSQ / AT+COPS? на управляющем порту
        |    hilink — веб-API модема на его шлюзе (Huawei /api/monitoring/status, ZTE /goform/…)
        v
   /dev/network-status-signal        <-- "<reg> <strength> <card> <monoSec>"
        |
        v
   твик iSpaceToolbox «Статус сети» -> иконка в статус-баре
```

Файл лежит в tmpfs (`/dev`), а НЕ в `/data/local/tmp`: он переписывается каждые несколько
секунд, а `/data/local/tmp` на этой голове — флеш. Путь задаётся `--signal-file` или
переменной `TBOX_SIGNAL_FILE`.

`monoSec` — секунды с загрузки из `/proc/uptime`. По ним твик проверяет свежесть: значение
старше 15 секунд считается протухшим, и он показывает «нет сети». Поэтому файл пишется
каждый такт, даже когда цифры не изменились.

## Значения

`reg` — тип сети в кодах головы: `1` = 2G, `3` = 3G, `6` = 4G, `10` = 5G, `0` = нет сети.
`strength` — палки 0..5 (у PPP считаются из `AT+CSQ` 0..31, у HiLink берётся `SignalIcon`).
`card` — всегда 1. Пока уровня ещё нет, вместо заглушки идёт анимация: во время работы
`wwan-up.sh` палки бегут по кругу, во время проверок приложения — мигают.

## Команды

```bash
tbox-icon.sh start        # запустить (отцепленным процессом)
tbox-icon.sh stop
tbox-icon.sh auto         # запустить, если не выключено в state/icon
tbox-icon.sh status       # работает или нет, содержимое файла, последние строки лога
tbox-icon.sh signal       # разовый опрос модема, ничего не запуская
tbox-icon.sh fake 4       # показать фиксированные 4 палки (проверка твика)
```

Выключатель — файл `state/icon` со словом `on`/`off` внутри. Пока там не `off`, `auto`
поднимает иконку после каждого подъёма модема.

## Чего здесь больше нет

Эмуляции блока TBOX по SOME/IP: офферов сервиса `0x8002`, ответов на `SubscribeEventgroup`,
TCP-listener'а на `30542`, событий `reportCellularNetworkInfo` и алиаса `192.168.62.37` на
`vlan62`. На машине без TBOX всё это работало вхолостую — цифры доезжали до
`com.tbox.service`, но слушателей у события было ноль.

Если понадобится вернуть (например, на машине с `tbox=1`), рабочая реализация лежит в
апстриме: `dsultanr/f515-usb-wwan`, файл `tbox/TboxWire.java`.
