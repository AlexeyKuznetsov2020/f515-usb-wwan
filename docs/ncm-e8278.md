# Huawei E8278 на голове F515 — исследование подключения по USB

> 2026-08-12. Цель: подключить USB-модем Huawei E8278 к голове F515 как источник
> интернета через проект `f515-usb-wwan`. **Итог: модем работает по USB.** Голова
> получает адрес от модема, интернет есть и у самой головы, и у приложений Android.
>
> Первая редакция этого документа заканчивалась выводом «по USB не поднимается,
> ограничение прошивки модема». Вывод оказался неверным — почему именно, разобрано
> в разделе [Где была ошибка](#где-была-ошибка). Ошибка была не в фактах: все
> измерения первой редакции подтвердились. Неверным был вывод из них.

## Кратко (TL;DR)

Модем — **Huawei E8278** (LTE + Wi-Fi роутер) в **HiLink/NCM**-режиме. Канал данных он
отдаёт не AT/PPP-портом, а **NCM-интерфейсом**, спрятанным за vendor-specific классом
`ff/02/16`. В ядре головы драйверов для этого нет:

```
# CONFIG_USB_NET_CDC_NCM is not set
# CONFIG_USB_NET_HUAWEI_CDC_NCM is not set
# CONFIG_USB_WDM is not set
```

Но **каркас для них в ядро встроен**:

```
CONFIG_USB_USBNET=y      CONFIG_MII=y      CONFIG_USB_NET_CDCETHER=y
```

— и `usbnet` экспортирует 41 символ. Значит недостающие драйверы собираются **внешними
модулями**, ровно как проект уже делает с `usbserial`/`option` для PPP-ветки. Собрано три
модуля (`cdc-wdm.ko`, `cdc_ncm.ko`, `huawei_cdc_ncm.ko`) **без единой правки исходников** —
апстримная таблица `huawei_cdc_ncm_devs` уже содержит нужную четвёрку `(12d1, ff, 02, 16)`.

После загрузки модулей модем становится обычным HiLink-роутером за `wwan0`, и дальше идёт
штатная HiLink-ветка `wwan-up.sh`: DHCP → маршруты → раздача приложениям.

## Что за модем

Опрос через AT-порт (PC UI, COM4 на ПК):

| Параметр | Значение |
|---|---|
| Производитель / модель | huawei / **E8278** (`AT+CGMM` → `E8278`) |
| Ревизия прошивки | `21.261.67.00.778` |
| IMEI | `3574359336*****` (скрыт) |
| SIM | `+CPIN: READY` |
| Сеть | зарегистрирован в **LTE** (`^RSSI:17`, `^LTERSRP:-107,-22`) |
| PID в рабочем режиме | `12d1:1506` (композит), в storage-стадии — `12d1:14fe` |
| Класс сетевого интерфейса | **CDC-NCM** за vendor-классом `ff/02/16` |

E8278 — LTE-модем со встроенной Wi-Fi точкой доступа («Turbostick»). По USB он отдаёт
сетевую карту NCM (сам делает NAT+DHCP, раздаёт `192.168.1.100`), плюс служебный PCUI/AT-порт
и два storage-интерфейса.

Раскладка интерфейсов (совпадает на ПК и на голове):

| Интерфейс | class | sub | proto | Что это |
|---|---|---|---|---|
| `4-1:1.0` | ff | 02 | **12** | PCUI/AT |
| `4-1:1.1` | ff | 02 | **16** | **NCM — канал данных** |
| `4-1:1.2` | 08 | 06 | 50 | CD-ROM |
| `4-1:1.3` | 08 | 06 | 50 | SD-ридер |

## Где была ошибка

Первая редакция закрыла оба пути так:

1. **«NCM невозможна — в ядре головы нет `cdc_ncm`».** Факт верный, вывод — нет. В ядре
   головы нет и `usbserial`, и `ppp_async` — а весь смысл проекта в том, что он их
   **довозит** собранными `.ko`. Проверять надо было не «есть ли драйвер», а «есть ли то,
   на что драйвер опирается»: `usbnet` в ядро **встроен** и экспортирует символы, значит
   `cdc_ncm` собирается внешним модулем. Офлайн-аудит в `spec/95` тоже отвечал на вопрос
   «что уже есть в ядре», а не «что туда можно догрузить».
2. **«PPP невозможна — `AT^SETPORT` отвергает код `10`».** Факт верный и до сих пор верен:
   модемного порта у HiLink-прошивки нет. Но он и не нужен — у этого модема канал данных
   NCM, а не PPP. Молчащий PCUI/AT-порт по той же причине ни на что не влияет: HiLink-ветке
   AT не нужен вообще.

То есть проверялись **обе ветки существующего проекта**, и обе честно не подошли — но
третья возможность (добавить драйвер, как уже сделано для serial) не рассматривалась,
хотя именно она и была штатным приёмом этого проекта.

## Решение: довезти три драйвера модулями

| Модуль | Зачем |
|---|---|
| `cdc-wdm.ko` | служебный WDM-канал NCM-функции (`CONFIG_USB_WDM=n`) |
| `cdc_ncm.ko` | собственно NCM поверх встроенного `usbnet` |
| `huawei_cdc_ncm.ko` | NCM Huawei за vendor-классом; тянет символы из обоих предыдущих |

Почему `huawei_cdc_ncm`, а не голый `cdc_ncm`: у Huawei NCM-функция объявлена
vendor-specific классом, и её нужно не только опознать, но и завести с двумя оговорками —
NDP в конце кадра и предпочтение NTB32. Всё это уже есть в апстримном драйвере.

Три модуля, а не один слитый (как `usbserialmerged2`): исходники нужны ровно апстримные,
без правок, а межмодульные символы `modpost` разрешает сам, раз все три собираются одним
проходом `M=`. Порядок загрузки: `cdc-wdm` → `cdc_ncm` → `huawei_cdc_ncm`.

## Сборка модулей

Ядро головы: `5.4.86-qgki-g310fb9b27fcd-dirty`, собрано Android clang 11.0.2 (r383902b1),
`CONFIG_CFI_CLANG=y`, `CONFIG_LTO_CLANG=y`, `CONFIG_THINLTO=y`, `CONFIG_MODVERSIONS=y`,
подписи модулей нет (`CONFIG_MODULE_SIG` не задан).

Исходники — CodeLinaro `msm-5.4`, тег **`LA.AU.1.3.2.r2-03600-sa8155_gvmq.0`**: это ровно
`SUBLEVEL = 86` и ровно та платформа (`sa8155_gvmq` — SA8155, Android-гость под
гипервизором, как на этой голове). Тулчейн — clang 11 + lld 11 (мажор тот же, что у
сборки ядра; от него зависят ABI CFI и раскладка `struct module`).

```bash
git clone --depth 1 -b LA.AU.1.3.2.r2-03600-sa8155_gvmq.0 \
    https://git.codelinaro.org/clo/la/kernel/msm-5.4.git
printf -- '-g310fb9b27fcd-dirty' > msm-5.4/.scmversion
adb shell zcat /proc/config.gz > f515-usb-wwan/modules/running.config
KDIR=$PWD/msm-5.4 f515-usb-wwan/modules/build-cfi.sh $PWD/f515-usb-wwan/modules/src/ncm
```

`.scmversion` обязателен: в конфиге головы `CONFIG_LOCALVERSION="-qgki"` и
`CONFIG_LOCALVERSION_AUTO=y`, то есть хвост `-g310fb9b27fcd-dirty` дописывает
`scripts/setlocalversion`. Коммит `310fb9b27fcd` — внутренний OEM-овский, в CLO его нет
(сборка вдобавок помечена `dirty`), поэтому строка фиксируется файлом. Иначе `vermagic` не
сойдётся и `wwan-up.sh` откажется грузить модуль.

## Проверки перед insmod

`insmod` — единственная операция во всём проекте, способная уронить голову, поэтому всё
проверяемое проверено заранее:

| Что | Результат |
|---|---|
| `vermagic` | `5.4.86-qgki-g310fb9b27fcd-dirty SMP preempt mod_unload modversions aarch64` — совпадает с `uname -r` |
| `__cfi_check` | есть во всех трёх (ядро с CFI не-CFI модули не принимает) |
| Раскладка `.gnu.linkonce.this_module` | размер `0x380`, `init_module.cfi_jt` на `0x178`, `cleanup_module.cfi_jt` на `0x338` — **байт в байт** как у заведомо рабочего `usbserialmerged2.ko` |
| `module_layout` в `__versions` | есть (CRC из `oem.symvers`, снятого с vendor-модулей головы) |
| Неразрешённые символы | все **113** найдены в `/proc/kallsyms` головы — «Unknown symbol» исключён |

## Подъём на голове

Модем приходит на шину виртуальным CD-ROM'ом (`12d1:14fe`) — сначала штатный
`tools/huawei-modeswitch`, после него `12d1:1506` с четырьмя интерфейсами.

Дальше есть одна тонкость: `option` из PPP-ветки матчит **всё устройство** `12d1:1506`
(`{ USB_DEVICE(HUAWEI_VENDOR_ID, 0x1506) }` в `modules/src/usbserial/option.c`), поэтому
если он загружен, то забирает и NCM-интерфейс — драйвер у интерфейса может быть только
один. Лечится передачей интерфейса без всякой пересборки:

```sh
printf %s 4-1:1.1 > /sys/bus/usb/drivers/option/unbind
printf %s 4-1:1.1 > /sys/bus/usb/drivers/huawei_cdc_ncm/bind
```

```
huawei_cdc_ncm 4-1:1.1: MAC-Address: 0c:5b:8f:27:9a:64
huawei_cdc_ncm 4-1:1.1: setting rx_max = 16384
huawei_cdc_ncm 4-1:1.1: NDP will be placed at end of frame for this device.
huawei_cdc_ncm 4-1:1.1: cdc-wdm0: USB WDM device
huawei_cdc_ncm 4-1:1.1 wwan0: register 'huawei_cdc_ncm' at usb-xhci-hcd.1.auto-1, Huawei CDC NCM device
```

Появился `wwan0` — дальше всё делает штатная HiLink-ветка:

```
== 2. режим модема          [ ok ] режим с рабочими интерфейсами
== 3. NCM-интерфейс Huawei  [ ok ] сетевой интерфейс wwan0 (драйвер huawei_cdc_ncm)
== 4. какой модем подключён [ ok ] HiLink-модем: сетевой интерфейс wwan0
== 5. адрес по DHCP на wwan0[ ok ] wwan0: 192.168.1.100 (шлюз 192.168.1.1)
== 7. маршруты и связь      [ ok ] связь есть (ping 8.8.8.8 через wwan0)
== 8. интернет приложениям  [ ok ] таблица vlan72: default переключён на wwan0
```

Итог на голове: `ping 8.8.8.8` — 48 мс, `dumpsys connectivity` показывает сеть `Tbox` как
`VALIDATED`/`everValidated{true}`, то есть Android считает модем настоящим интернетом и
пускает туда трафик приложений.

## Что изменилось в проекте

- `modules/src/ncm/` — апстримные `cdc-wdm.c`, `cdc_ncm.c`, `huawei_cdc_ncm.c` + Makefile;
- `modules/prebuilt/` — собранные `cdc-wdm.ko`, `cdc_ncm.ko`, `huawei_cdc_ncm.ko`;
- `scripts/wwan-up.sh` — стадия **«NCM-интерфейс Huawei»** (загрузка трёх модулей, отбор
  интерфейса у `option`, ожидание netdev) плюс стадия **«режим модема»** поднята из
  PPP-ветки выше определения типа: пока модем в storage-режиме, его не опознать никак;
- `app/` — три новых `.ko` в списке раскладываемых файлов (`Keeper.java`) и в сборке
  ассетов (`build.sh`).

Wi-Fi как запасной вариант никуда не делся и по-прежнему проще, если USB не нужен: E8278
сам по себе Wi-Fi роутер. Но USB-путь теперь рабочий, и на нём голова не занимает Wi-Fi.

## Приложение: собранные данные

**Стенд:** голова по adb-TCP (root), модем Huawei E8278, ПК Windows + WSL.

**Ядро головы:**

```
uname -r     -> 5.4.86-qgki-g310fb9b27fcd-dirty
/proc/version-> Android (6877366 based on r383902b1) clang version 11.0.2, LLD 11.0.2
конфиг       -> CONFIG_USB_USBNET=y, CONFIG_MII=y, CONFIG_USB_NET_CDCETHER=y,
                CONFIG_CFI_CLANG=y, CONFIG_LTO_CLANG=y, CONFIG_MODVERSIONS=y,
                CONFIG_USB_NET_CDC_NCM / HUAWEI_CDC_NCM / USB_WDM  — не заданы
kallsyms     -> 41 символ __ksymtab_usbnet_*, есть cdc_parse_cdc_header, mii_nway_restart
```

**Модем на ПК (Windows, до переноса на голову):**

```
USB\VID_12D1&PID_1506                                    (композит)
USB\Class_ff&SubClass_02&Prot_16  -> HUAWEI Mobile Connect - Network Card (CDC-NCM)
USB\Class_ff&SubClass_02&Prot_12  -> HUAWEI Mobile Connect - PC UI Interface (COM4)
usbcdcncm\compat&ext_ctrl         -> Extra Control Device   (это и есть WDM-канал)
шлюз/DNS 192.168.1.1                                     (модем сам роутит)
```

**AT-опрос (COM4, PC UI) — данные первой редакции, остаются в силе:**

```
ATI          -> huawei / E8278 / Revision: 21.261.67.00.778
AT+CPIN?     -> +CPIN: READY
AT^SETPORT?  -> ^SETPORT:A1,A2;12,16,A1,A2
AT^SETPORT="A1,A2;10,12,16,A1,A2" -> ERROR   (модемного порта у HiLink-прошивки нет)
AT^SETPORT="A1,A2;12,16,A1,A2"    -> OK      (исходный режим восстановлен)
```

Вывод из этих строк прежний: **PPP-порт включить нельзя**. Просто он не нужен.
