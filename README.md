# F515 USB WWAN — мобильный интернет из USB-модема на голове F515

Подключаешь USB-модем в голову F515 — приложение поднимает его как интернет для головы
и для остальных приложений Android. Одна кнопка, без пересборки boot/vendor_boot, без
туннелей. Умеет все основные типы модемов и определяет тип сам:

| Тип | Примеры | Что нужно |
|---|---|---|
| **HiLink (CDC-Ethernet / ECM)** | ZTE MF833R, Huawei E8372h-153 (`14db`), E3372h-153 (`14dc`) | ничего — ядро головы уже умеет `cdc_ether`, нужен только DHCP |
| **HiLink на NCM** (канал данных — NCM за vendor-классом `ff/02/16`) | Huawei E8278 / E3372s / E8372 | три модуля ядра (`cdc-wdm`, `cdc_ncm`, `huawei_cdc_ncm`), дальше тот же DHCP — всё есть в репозитории |
| **RNDIS / Composite** (класс `e0/01/03` или `02/02/ff`) | MTS 81332FT (ZTE MF90 / Marvell PXA1802) и др. | модуль ядра `f515_rndis` (CFI-safe, автономный парсер CDC), дальше DHCP — всё есть в репозитории |
| **PPP / Stick** (модем отдаёт AT/PPP-порты, `12d1:1506` и др.) | Huawei E17x / E1750 / E3272 / Stick-прошивки | modeswitch (автоперебор методов) + два модуля ядра + дозвон pppd — всё есть в репозитории |

![Успешный запуск: приложение на приборной панели, все стадии отработали, интернет есть](docs/img/screenshot.png)

Этот репозиторий является единым преемником двух архивных проектов —
[f515-hilink-wwan](https://github.com/dsultanr/f515-hilink-wwan) и
[f515-huawei-wwan](https://github.com/dsultanr/f515-huawei-wwan): один скрипт, одно
приложение, поддержка всех типов подключения, плюс автозапуск после перезагрузки головы.

## Установка

1. Скачай `app/F515UsbWwanApp.apk` из этого репозитория (или собери сам — `app/build.sh`).
2. Установи на голову — через USB-флешку и штатный установщик Toolbox (`pm install` на
   этой прошивке отключён политикой), либо через EngMode-инъекцию. Подробнее —
   [app/README.md](app/README.md).
3. Вставь модем в USB, открой приложение, нажми **Включить**.

Готово: модем поднят, DNS фантомной TBOX-сети починен, интернет виден и приложениям
Android, а в статус-баре вместо крестика — палки сигнала этого самого модема.

## Кнопки

- **Проверка** — диагностика (`--check`), ничего не меняет
- **Включить** — поднять модем и раздать интернет приложениям Android (`--system`)
- **Выключить** — остановить pppd / сетевое подключение (`--down`)
- **Автозапуск** — включить/выключить подъём после перезагрузки головы, посмотреть
  состояние сторожа, снять блокировку безопасного режима
- **Иконка сети** — включить/выключить показ сигнала модема в статус-баре, разово
  посмотреть, что видит модем
- **DNS** — задать свой DNS-сервер для приложений вместо того, что дал оператор
  (`--dns=1.1.1.1`, обратно `--dns=auto`); действует, пока интернет идёт через модем —
  подробности в [docs/app-network.md](docs/app-network.md)
- **Интернетометр** — открыть проверку скорости в браузере
- **Форматировать SD** — выбрать съёмную SD/TF-карту (модема или флешку) из списка и
  стереть её (MBR + exFAT, с подтверждением) — необратимо

## Иконка сотовой сети

На этой машине блока TBOX нет (`config tbox=0`), поэтому штатная панель сотовую иконку не
создаёт вовсе — в статус-баре пустое место. Приложение опрашивает модем (у PPP по
`AT+CSQ`/`AT+COPS?`, у HiLink через его веб-API) и пишет уровень в tmpfs-файл
`/dev/network-status-signal`, а рисует иконку твик **iSpaceToolbox «Статус сети»** — он
инжектит агент в `com.android.systemui`, не включая опцию TBOX, чтобы не ломать сброс ТО.
Твик нужно включить в тулбоксе, иначе файл никто не читает.

Эмуляции блока TBOX по SOME/IP в этом форке нет: без TBOX она работала вхолостую. Если
понадобится машина с `tbox=1` — рабочая реализация осталась в апстриме.

На интернет это никак не влияет. Иконка включается сама после подъёма модема, пока её не
выключили кнопкой «Иконка сети». Как устроено и откуда берутся цифры —
[docs/status-icon.md](docs/status-icon.md).

## Автозапуск после перезагрузки

Включается кнопкой в приложении и по умолчанию выключен. После ребута приложение ждёт
локальный adbd (тот поднимается не сразу), поднимает модем и оставляет сторожа, который
раз в минуту проверяет связь и передозванивается, если она отвалилась.

Единственная операция во всём проекте, способная уронить голову, — `insmod` модуля ядра,
поэтому автозапуск обвешан защитой: счётчик «заходов, из которых мы не вернулись»,
маркер `insmod-inflight` как точная подпись падения на загрузке модуля, файл-выключатель
и задержка после загрузки. Как это устроено и что делать, если голова всё-таки ушла в
цикл, — [docs/autostart.md](docs/autostart.md).

## Структура репозитория

| Путь | Что |
|---|---|
| `scripts/wwan-up.sh` | главный скрипт: определяет тип модема, режимы HiLink/ECM/NCM/PPP и поднимает связь |
| `scripts/wwan-boot.sh` | автозапуск: защита от бутлупа + watchdog |
| `scripts/dial.sh`, `at.sh` | connect-скрипт pppd и отправка AT-команд (только ppp-ветка) |
| `scripts/format-sdcard.sh` | список съёмных карт и форматирование выбранной |
| `scripts/tbox-icon.sh` | иконка сотовой сети: запуск/остановка/состояние |
| `tbox/` | исходник `TboxWire.java` (опрос модема и запись сигнала в файл), сборка, готовый jar |
| `modules/` | исходники `usbserialmerged2`/`ppp_async`/NCM-тройки, готовые `.ko`, скрипт пересборки |
| `tools/` | `huawei-modeswitch` — утилита переключения режимов с перебором методов, поддержкой CSW и диагностикой |
| `app/` | Android-приложение (кнопки над теми же скриптами), исходники + готовый APK |
